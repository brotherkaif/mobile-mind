# Executive summary

This audit compares the OKR Template Knowledge Bundle against the latest OKF v0.2 specification. The bundle is structurally close to conformance but has three categories of issues:

1. **Conformance violations** (must fix)
   - Three non-reserved markdown files lack frontmatter and `type`.
   - One reference concept uses non-conformant `status` and `verified` values.
2. **Structural inconsistency**
   - The directory `output/` is singular while the bundle documentation and the audit skill expect `outputs/` (plural).
3. **Opportunistic improvements**
   - Directory `index.md` files are sparse.
   - No example concept or playbook is present to demonstrate the format.

# Conformance findings

## 1. Missing frontmatter on non-reserved markdown files

**Status:** Conformance violation  
**Files:**
- `assets/images/README.md`
- `assets/raw/README.md`
- `output/README.md`

OKF §3.1 reserves only `index.md` and `log.md`. `README.md` is not a reserved filename, so these files are concept documents. Per OKF §4.1 and §11, every non-reserved `.md` file MUST contain parseable YAML frontmatter with a non-empty `type` field. These files currently contain only a body heading and instructions.

**Remediation:** Add frontmatter with a descriptive `type` (e.g., `Directory Guide`), `title`, `description`, and `generated` provenance.

## 2. Invalid `status` and `verified` values in `references/okf-v0.2.md`

**Status:** Conformance violation  
**File:** `references/okf-v0.2.md`

The file currently declares:

```yaml
status: active
verified: human-reviewed
```

OKF §5.4 defines `status` values as `draft | stable | deprecated`. The value `active` is not conformant.  
OKF §5.2 defines `verified` as a list of `{ by, at }` mappings (or a single mapping), where `by` is an actor and `at` is an ISO 8601 datetime. The string `human-reviewed` is not a valid value.

**Remediation:** Change `status` to `stable` and rewrite `verified` as a mapping such as `{ by: human:reviewer, at: 2026-07-31T14:26:00Z }`.

## 3. `output/` directory name conflicts with documented `outputs/`

**Status:** Structural inconsistency  
**Files:** `index.md`, `README.md`, `.agents/skills/okf-audit/SKILL.md`

The bundle root contains `output/` (singular). However:
- `index.md` links to `[outputs](outputs/)`.
- `README.md` documents `outputs/`.
- The audit skill instructs writing to `outputs/audit-YYYY-MM-DD.md`.

This is not a strict OKF conformance issue because directory names are not reserved, but it breaks internal consistency and the skill's own output path.

**Remediation:** Rename `output/` to `outputs/` and update the one affected file path.

# Observations and recommendations

## 3. Sparse subdirectory indexes

`concepts/index.md`, `playbooks/index.md`, and `references/index.md` contain placeholder text. This is acceptable for a starter template, but adding one example concept and one example playbook would make the template self-documenting and provide a concrete conformance reference.

## 4. Latest spec datetime guidance

The live OKF v0.2 specification now states that every timestamp-valued key MUST be an ISO 8601 datetime with an explicit UTC offset. The bundle's `generated.at` values already comply. If `stale_after`, `verified.at`, or source `last_modified` fields are added later, they should use datetimes rather than plain dates.

## 5. Actor convention

`generated.by: process:okr-template/1` is acceptable under OKF §7 (`process:<id>`). Consider whether the `/1` suffix is intended as a version; if so, the actor convention for tools is `<producer>/<version>`, e.g., `process:okr-template/1` is still valid as a process ID but could be clarified.
